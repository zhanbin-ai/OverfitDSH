# @deepseek-ai/dsh-api-git

English | [中文](README.zh.md)

## Summary

Use this package to read and shape the Session workspace's repository from the web client: one typed Remote namespace, `git`, with `status`, `diff`, `stage`, `unstage`, `commit`, and `history`. Every command runs through `ctx.subprocess` as an explicit argv with a scrubbed environment (`GIT_CONFIG_COUNT=0`, no prompts, no optional locks, literal pathspecs); the working directory comes from the Session header (`cwd`, with the sandbox policy root as its no-cwd fallback), so a Client names only a Session id, and the repository root is located per call with `git rev-parse --show-toplevel`.

## Use this package

Mount the package beside `@deepseek-ai/dsh-subprocess`, the sandbox policy, and the Session store (the web bundle does so next to the workspace file service), and consume it on the Client through the api-remotes assembly.

| Method | Returns | Purpose |
|---|---|---|
| `status(sessionId)` | `GitStatus { repoRoot, branch, entries }` | One `--porcelain=v1 -z` snapshot; entries carry index/worktree letters and rename pairs |
| `diff(sessionId, path, staged)` | `GitDiff { path, staged, text, truncated }` | One unified diff; an untracked path reads as an addition against `/dev/null` |
| `stage(sessionId, paths)` | `GitStatus` | `git add -- <paths>`, then the fresh snapshot |
| `unstage(sessionId, paths)` | `GitStatus` | `git reset -- <paths>` (unborn HEAD falls back to `git rm --cached`), then the fresh snapshot |
| `commit(sessionId, message)` | `GitStatus` | `git commit -m`, then the fresh snapshot |
| `history(sessionId)` | `GitCommit[]` | Recent `%h␉%s` lines, newest first |

### Failure codes

`git/not-repository` (the workspace is outside any repository), `git/command-failed` (a nonzero exit with a bounded stderr tail), plus the carrier's `gateway/bad-request` for unusable input. Callers branch on the code, never on message text.

### Configuration

| Field | Default | Meaning |
|---|---|---|
| `timeoutMs` | `20000` | Milliseconds one git command may run before it is terminated |
| `maxDiffBytes` | `262144` | Inclusive byte cap on one diff answer, and on the raw-content fallback |
| `maxHistory` | `30` | Largest number of commits one history answer carries |

## Understand the implementation

<details>
<summary>Implementation internals — click to expand</summary>

The Host owner is `Git extends TypertRemoteService`; a `gitWorkspaceScope` Typert lookup resolves the Session header without activating an Agent, and each method receives that scope as its wire-resolved first parameter. The runner adapts the workspace-changes deliverable's subprocess pattern: collect-mode stdio, a fixed termination grace, and `readFrom(0)` readers that stay readable after exit. The `/typert` and `/remote` artifacts are generated by the dsh-typert-generator during the Host pass; the package contributes no browser half, so the api-remotes assembly mounts the namespace for Client consumers and re-exports its payload vocabulary.

</details>

## Known limitations and deferred work

- **No file watcher** — snapshots are pull-based; nothing subscribes to `fs/observed`.
- **Path-level staging only** — no hunk staging, stash, or branch/push operations.
- **One working tree per call** — nested repositories and gitlinks are ordinary paths to these commands.
- **No AI commit message** — the LLM-assisted message is a separate increment; this namespace ships the plain commit.

**Runtime note:** no companion entry. The service holds no mutable state beyond the resolved executable; each answer is derived from the repository at call time.
